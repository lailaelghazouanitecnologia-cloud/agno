## Instructions
Write comprehensive tests for this module. You must:

1. Read the module implementation to understand what it does
2. Write unit tests covering:
   - Normal/happy path cases
   - Edge cases (empty input, boundary values, etc.)
   - Error cases (invalid input, missing data, etc.)
3. Write the test file using write_file
4. Run the tests to verify they pass

## Rules
- Tests should be thorough — aim for high coverage
- Each test should be independent
- Use clear test names that describe what's being tested
- After writing, RUN the tests and report results
- If tests fail, fix the implementation (not the tests) unless the test is wrong
